# v0.1.54 — Configurable reported renderer name for the QA lab

The OpenGL `GL_RENDERER` name can now be selected independently of device identity profiles. The default reported label is `Mali-G78`; `null` or `native` disables the alias. This changes a reported string only. The image continues to render through its existing ANGLE/SwiftShader backend. GPU capabilities, vendor, extensions, Vulkan device properties, hardware acceleration and security properties are unchanged.

The native artifact builder derives a small immutable driver artifact from the exact pinned platform library, verifies its permitted ELF transformation and mounts it read-only in the owned Android runtime. Native `renderer configure --json-stdin` persists the setting and uses the existing `up` convergence owner. `renderer status` observes the actual binding, source digest, read-only ownership and zygote mappings; a saved configuration or successful setter alone is not proof of application. Disable through the same native convergence path to restore the untouched image library and refresh inherited mappings.

The panel exposes this independent setting under device profiles as **reported renderer name for QA**. It is not an identity-profile JSON field. Saving stores the controller default. Applying publishes it to installed hosts; new devices inherit that host default at creation, including explicit native/custom labels. The first native boot retains the configured proxy-import arguments.

Host settings live in `/etc/xenoid-fleet/qa-graphics.json`. The default applies to future servers after their normal panel provisioning. The idle reconciliation timer retries deferred devices. It exits without native imports or registry reads when its settings generation has been acknowledged. Active workers and their surviving child cgroups are never interrupted. A worker holds a shared lifecycle gate; graphics convergence holds the exclusive gate. At a quiescent iteration boundary, after recorded GEN recovery and before any app actions, the owning worker can reconcile a changed default or a cold-restarted runtime. Its warm path checks a cached proof against the immutable identity, PID/start time, desired settings and source generation without repeating full native status or `up`.

Native GEN journals, general convergence journals, pending profile targets and uncommitted QA regeneration receipts defer renderer changes. An interrupted renderer-only reuse plan can resume through the existing native executor under the same native operation lock. This exception requires the unchanged configuration, artifact/input identities, container, storage UUIDs, image/boot identities and protection state; it rejects build, recreate, identity, proxy, GEN or other non-renderer work. The QA helper never clears or rewrites the saved journal. A newer panel label waits for the exact older native intent to finish, then follows the normal status/configure path; changing the panel default cannot alter the saved plan. Their original bytes, targets, decisions and identity policy digests are preserved. Native convergence remains the only graphics runtime owner. Completion requires fresh readback and a marker containing the runtime epoch, desired-settings digest, source generation and renderer proof. A concurrent newer settings save cannot be acknowledged by an older pass.

Cold starts keep the existing owned container when only the daemon APK input differs and both verified boot contracts match. The normal convergence owner starts that container and verifies its components; incompatible boot, storage, network or ownership contracts keep their existing rejection or replacement behavior.

Operational commands:

```bash
printf '%s\n' '{"renderer_label":"Mali-G78"}' | sudo xenoid-fleet graphics configure --json-stdin
sudo xenoid-fleet graphics reconcile all
sudo xenoid-fleet graphics status all
# Restore the actual backend-reported label through the same owner:
printf '%s\n' '{"renderer_label":null}' | sudo xenoid-fleet graphics configure --json-stdin
sudo xenoid-fleet graphics reconcile all
```

The APK, existing scenario source/timing, official Xenoid touch path, display geometry, reported refresh rate and 1-CPU/2-GiB container limits are unchanged. A label alias does not make software rendering equivalent to a physical Mali GPU. Real app/WebView rendering and rollback must be verified before wider rollout.
