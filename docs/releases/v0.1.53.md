# v0.1.53 — Larger US SIM-number generation pool

The legacy US MSISDN template had two variable digits, giving only 100 possible numbers across the US profile pool. As more identities were reserved, otherwise valid GEN candidates repeatedly collided with an existing number.

Explicit US generation version 2 samples the full pinned US national-number pattern deterministically. It uses a separate HMAC domain, checks each candidate against the existing country rules and fails explicitly if generation cannot produce a valid candidate. New numbers span more than a billion syntactically valid combinations.

These are synthetic QA identifiers. Generation does not verify an active subscription or ownership of a telephone number.

Version 1 remains the default for legacy callers. Its seed labels, template and encoded profiles are unchanged. Existing stored profiles and journal targets reload exactly; validation accepts both the original demonstration block and the larger version-2 pool. The catalogue's snapshot version, original US pattern and carrier definitions remain unchanged.

New US creation, country selection and new GEN candidates select version 2 explicitly. The complete location target is journaled even when GEN does not receive a country flag. Legacy journals without a pinned target retain their original version-1 derivation.

Collision retries continue with append-only attempt numbers after each bounded batch instead of restarting at the first eight candidates. The durable active/prepared pointers locate the current attempt directly. A reserved or prepared target is reused exactly, and normal identity, ownership, context and acknowledgment checks remain required.

The change is in host-side Python and catalogue data. The daemon Java code, APKs, Android image, official native touch path, display settings and container resource limits are unchanged. Source publication does not itself regenerate a device or replace a recorded target.
