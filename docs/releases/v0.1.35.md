# v0.1.35: bounded live profile snapshots

Live profile observation collects Android property values in one snapshot and verifies their presence independently through Android's property-type enumeration. Only the selected keys reach the host parser. Required keys, values and duplicates are checked, along with display size and density, memory, CPU declarations, native input axes and Bluetooth state. The caller's deadline continues to apply. Incomplete, invalid and timed-out observations fail acceptance with their own diagnostic codes; an observed value mismatch continues to fail profile verification.

This addresses a reproduced startup failure under a real 1 CPU / 2 GiB limit: the previous 191-process property collection was incomplete at its caller's 10-second deadline, while a separate 30-second observation finished in 12.4 seconds and matched all 191 properties. Source, runtime ownership, storage and resource counters were unchanged during that comparison.

The change is in host observation code. APKs, official Xenoid input, configured display and pacing, hard resource limits, and Android runtime image inputs retain their existing contracts. The regeneration recovery, memory reclaim headroom and QA close-control improvements from v0.1.34 are included.

Focused regressions, source integrity and actual device observations are recorded separately. A source release alone does not establish long-running fleet stability.
