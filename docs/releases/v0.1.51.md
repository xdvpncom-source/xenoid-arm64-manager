# v0.1.51 — observe workflow steps with less idle UI work

During the post-permission 90–120-second wait, a stable ordinary foreground no longer triggers periodic full UI collections by default. The scenario still checks focus every five seconds and collects a fresh hierarchy on entry, after input, when focus changes or when a previous read needs retrying. The next workflow stage always obtains a new screen observation. `PASSIVE_WAIT_PERIODIC_UI` controls this behavior in the script.

Active ad handling uses `AD_STATE_POLL_SECONDS` (five seconds by default). A known countdown can delay the next collection until its remaining time, capped by `AD_COUNTDOWN_RECHECK_SECONDS` (15 seconds); after input or with a usable close control, the existing two-second cadence applies. These timings remain editable in the script.

This release also includes the Skip follow-up change: Skip is an intermediate action, a fresh screen is read before the next input, and a visible Close, Dismiss or X control takes priority. An unchanged Skip is attempted once by default, with `AD_SKIP_SAME_STATE_ATTEMPT_LIMIT=0` available to disable that limit. Configured-store recovery and verified native Back remain intact.

Regression coverage checks passive-wait read counts, focus changes and failed-read recovery, countdown pacing, post-input reads, and the Skip-to-Close sequence. No APK or native backend change is required.
