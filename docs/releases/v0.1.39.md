# v0.1.39: reserve native identities before managed regeneration

Independent native generators can choose a value already used by another
device. The panel now reserves the actual native candidate before the native
regeneration journal is prepared. The existing authenticated SSH poll and ACK
path carries the request; no additional public service is introduced.

The controller enrolls actual current observations from the complete active
cohort. SQLite transactions and unique keyed digests reserve Android ID, serial,
IMEI, boot ID, Bluetooth address, hostname, device name, filesystem ID and the
native-declared DRM ID, together with native IMSI, ICCID and MSISDN. A value must
also differ from that device's preceding generation. IMEISV is a finite software
revision and is checked for a change without requiring global uniqueness.

A confirmed collision can generate another candidate before preparation. An
unknown acknowledgement keeps the same transaction and candidate reserved.
Prepared transactions retain their original target. Finalization requires the
matching native commit, exact native identity readback and native SIM sidecar
proof before releasing the preceding generation's current claims.

These guarantees require the coordinated managed-writer cutover and complete
cohort enrollment. Installing host files alone does not enroll existing workers.
Fresh observations reconcile additions and eligible container replacements
automatically. New reservations wait for a complete current cohort; exact
already-reserved operations can still finish during an unrelated addition.
Stopped or removed members retain their claims. Rebinding a replacement
container requires the same instance, unchanged current values and no pending
native transaction.
Native container replacement also verifies an existing active SIM/location
profile against the new runtime epoch. This uses the existing location
convergence path without creating another SIM profile or changing its IDs;
healthy reuse of the same container remains unchanged.
Manual native CLI regeneration without the optional managed callback remains
outside this controller ledger. Uniqueness covers current and pending values;
retired historical values are not reserved forever.

Running devices publish identity observations independently of script workers
and APK assignments through the existing authenticated poll path. One device is
read per poll, using a nonblocking native lock and an eight-second read budget.
Unavailable or busy devices publish no substitute values. The controller checks
the current inventory binding again before accepting a result. A slow periodic
refresh continues when scripts are disabled; incomplete cohorts refresh sooner.
This prevents an unassigned new device from indefinitely waiting for an APK
before its identity can be enrolled. Legacy run-only poll requests still work.

Fresh cold seeding initializes a nonzero filesystem ID, hostname and model-based
device name from the already-owned native IDs. Initial convergence uses the
existing native setters and verifies their readback and filesystem publication.
Applied identities and GEN-owned values are preserved. Observation accepts the
native empty initial SIM epoch; generated targets still require their full
32-hex epoch. Previously applied legacy data with missing identity fields needs
separate explicit admission rather than a silent identity rewrite.

Cold-boot revalidation also restores missing SELinux labels on the known
filesystem-ID and hostname sidecars replaced by the native writers. It validates
the full stored profile and every leaf before restoring either label. Identity
values, owners and modes stay unchanged; conflicting labels or values still
stop convergence.

The installed Pixel 6a build, display, CPU, memory and storage contract stays
coherent. Build fingerprints identify the installed build and may legitimately
match across devices. No fingerprint, manufacturer TAC, hardware DRM certificate
or Google certification is invented. The existing native IMEI TAC has not been
independently established as manufacturer-issued for Pixel 6a.

The source-built CPU-information overlay and cold/live profile publishers now
select the `Hardware` label from the validated profile. This removes the fixed
Raven label when the selected profile is bluejay. It does not replace the host
kernel, camera or sensor HALs, alter SELinux enforcement, or turn the container
into physical Pixel hardware. Ordinary-app AAID, SSAID and MediaDrm results need
their own API observations and are separate from native declared identifiers.

The VPN APK, official Xenoid input path, 1080×2400 display at 420 logical DPI and
429 physical PPI, advertised 60 Hz mode, 15 FPS renderer pacing and real
one-CPU/two-GiB resource limits are unchanged.

Local qualification: 1,297 public tests, with 1,289 passes and eight platform
skips, plus 16 native bundle tests. Controller tests, live canary results and
rollout results are recorded separately.

An isolated live canary completed two managed native generations and three
ordinary-app API captures. All 13 native values changed in each generation;
app Android ID and the 16-byte DRM identifier changed too. The raw microG
advertising-ID Binder returned distinct UUIDs after each generation, while the
official Google client remained unavailable. Its reported DRM `L1` property
does not establish hardware certification or protected playback. The ordinary
ActivityManager API reported approximately 7.55 GiB of host RAM, despite the
6 GiB JSON model and real 2 GiB container limit. These limits are retained in
the private measurement report; this is not full physical Pixel equivalence.
