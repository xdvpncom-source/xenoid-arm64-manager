# v0.1.42 — installer metadata in the official native app path

Panel-uploaded APKs continue to use the official `/usr/local/bin/xenoid-fleet run ID -- app install PATH` command. The owning daemon's `RootHelper.installApk` now invokes `pm install -r -i com.android.vending` inside Android. This records the requested installer package while retaining standard reinstall behavior. It does not establish a Google Play download, license or device certification.

The release adds the `RootHelper.java` source overlay to the existing native source bundle. Future hosts build the daemon through the existing validated artifact recipe and their own signing key. Existing compatible instances can receive the daemon through the official component deployment path; an old runtime image remains identified by its original immutable record. The QA compatibility guard accepts a changed daemon source-input digest only when the remaining artifact, tool, boot and seed-security contracts remain equal.

The Bluetooth HAL asset, other native binaries, Android image inputs outside the daemon component, uploaded APK contents, shared scenario source and its settings are unchanged. The release does not replace the official install command with a panel ADB adapter. Central controller installer-version metadata points future host preparation at this release.

The actual canary completed a fresh install and reinstall through the official `xenoid-fleet run ID -- app install PATH` command. An ordinary app observed `com.android.vending` through both modern and legacy installer APIs; initiating and originating package values remained null. The reinstall preserved its UID, private preferences and APK digest. The test app and staging files were removed afterward; the production VPN APK was not reinstalled. Native convergence retained the existing container and image.

Validation includes focused Java tests for the exact installer command, shell quoting and failure propagation, plus compatibility tests that reject unrelated artifact, image, tool or seed-security changes. Installer metadata does not establish Play Store distribution or certification.
