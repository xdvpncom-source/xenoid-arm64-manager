# v0.1.50 — recheck the ad after Skip

Skip now counts as an intermediate ad action. The scenario waits for a fresh screen observation, then checks for the remaining Close, Dismiss or X control. When Close and Skip are both visible, Close takes priority. If Skip opens a configured store, the existing verified Back recovery returns to the ad and prefers its remaining Close control.

An unchanged Skip control is attempted once by default. The script setting `AD_SKIP_SAME_STATE_ATTEMPT_LIMIT` controls that count; zero disables the limit. The existing countdown handling, fresh native navigation checks and foreground confirmation remain in place.

Regression coverage includes Skip followed by Close, Close taking priority over Skip, unchanged Skip handling and store-return follow-up. This release changes the shared scenario and its defaults, with no APK or native backend modification.
