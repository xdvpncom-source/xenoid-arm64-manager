# v0.1.41 — managed script handoff

A completed managed run could retain its last identity message while a successor waited in the controller queue. Replaying that message attempted to acknowledge a terminal or superseded run and prevented terminal event ingestion. The central controller now validates already committed terminal evidence through a read-only path, then ingests its events normally. It sends no new ACK and does not reserve, finalize, enroll or release identity claims on that path. Pending and unverified identity work remains held.

The focused controller patch is included for review and compatible central deployments at `patches/controller-terminal-identity-handoff.patch`. It is not installed into execution hosts. Exact compatible `device_scripts.py` source SHA256 values:

- Before: `4585dd83ee7c1a498bed5b211ce06dc2d41f146d33530adedf4a8ed3d3ac4e52`
- After: `82a93b51a41f02792e8e709033ae334f7011d0eed463d04020692021c2039b9f`

Existing native82 sources, runtime images, DEX/ELF assets and all QA host helpers are unchanged. Existing v40 execution hosts remain compatible; central deployment does not require their restart or a native rebuild. Future host installers use the v41 release metadata.

Candidate validation includes real SQLite/Fernet terminal-current and superseded-run regressions, pending/ownership/proof negatives and real-filesystem publication/rollback cases. Stable publication waits for the actual controlled one-generation canary and paired ordinary-app API measurement; no runtime acceptance is inferred from local tests.
