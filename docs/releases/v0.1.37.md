# v0.1.37: preserve native control while an Android VPN is connected

An application VPN can route Android's ADB reply into its own tunnel. The Android
runtime remains alive, but the original ADB connection and the daemon forwarded
over that connection become unreachable. A failed proxy agent can also remain
unrecovered after an earlier successful resource check.

## Changes

- Keep the owned native ADB reply on its verified physical underlay. The single
  IPv4 rule matches the immutable device's address, its own bridge gateway,
  native TCP source port and actual adbd UID. It changes neither public traffic
  routing nor the application VPN. Native input continues through Xenoid.
- Apply and maintain this protection before native display or UI checks, using
  the existing resource entry point and timer. Bind changes to the current
  container, init generation, network namespace, lease, interface and listening
  socket. Record ownership before adding a rule and restore only that exact rule.
- Check the actual proxy agent during an ordinary same-boot maintenance pass.
  Establish missing native bootstrap readiness before reconciling the saved
  proxy. Pending network recovery remains separate from valid graphics settings;
  there is no automatic public direct fallback. The panel exposes a separate
  maintenance timeout, default 180 seconds; zero removes the aggregate budget.
- Load the official factory toolchain environment before timer-side native
  imports, preserving installed artifact identities during recovery.
- Distinguish an unreadable userspace epoch from a proven runtime change. Before
  navigation input, a positively cleaned reader can reject the consumed offer
  and obtain a fresh ordinary observation. A genuine runtime change, uncertain
  cleanup or lost input acknowledgement remains an error.
- Install and stage the complete fifteen-file host dependency set, including the
  new control-route helper. Keep the existing ten-second live grid behavior.

## Validation

The composed source passed 1,180 public unit tests: 1,172 passed and eight were
skipped for platform requirements. Focused ownership, rollback, watchdog,
navigation freshness and controller dependency-closure regressions are included.
The panel form passed 31 local assertions against its actual served functions.

On the production canary, the ordinary saved workflow completed two full cycles
during a 458-second read-only observation. Each included the 100-second
foreground VPN hold followed by ordinary app closure and data clearing. Twelve
connected-VPN probes confirmed that native ADB and the original forwarded daemon
remained reachable while the public test route still selected the VPN tunnel.
The same container generation retained its one-CPU/two-GiB limits and had no new
OOM or OOM-kill events. Transient stock UI-dump warnings recovered without a
failed cycle. This is canary qualification; full-fleet rollout and observation
are recorded separately. Continuous between-probe connectivity and external
VPN Internet reachability were not established by this observation.
