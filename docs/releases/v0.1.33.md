# v0.1.33

A daemon can already be listening inside a healthy Android container while an
ADB reconnect has removed its leased host-side port forward. Earlier startup
could then time out while polling that missing host endpoint.

The existing backend now reconciles only the selected runtime's leased forward.
It checks the immutable container and its running process identity around ADB
operations, verifies the exact selected serial and ports, and creates a missing
mapping with `--no-rebind`. An existing foreign or ambiguous mapping fails
without replacement. A correct warm mapping is neither rebound nor reconnected.
Readiness requires a verified mapping and a fresh successful host HTTP response;
if a mapping is repaired after a response, that response is discarded and the
endpoint must be proved again.

Recovery stays within the existing default/start and parent time budgets. It
does not add a global ADB server restart, recursive startup, or an Activity launch
to the ordinary non-Activity path. Normal ownership, pending-journal and final
native acceptance checks remain in force.

Fifteen runtime-free regressions exercise missing and lost forwards, reconnect,
foreign mapping rejection, exact-owner races, deadline exhaustion, warm no-op,
and the relationship between forward ownership and the HTTP proof. Existing
real context/artifact tests show that both full and boot image keys remain
unchanged, with a positive control that changes an actual render input.

A bounded exact-owner canary restored a naturally missing forward in about
0.49 seconds and proved the host transport ready. Only the leased mapping was
added; other forwards, runtime/native state, storage, configuration, signer,
journal and installed source remained unchanged. That probe did not install
source or run native UP. Sanitized outcome provenance is bound to digest
`3622fde9fc02febab17bbe8ce8f28680e17053e057e08f4a3ad5b66e5fd63dab`.
After this transport repair, the original installed v0.1.32 CLI resumed the
same recorded operation and plan successfully, retired its journal, and passed
`doctor --require-runtime`. Runtime/storage/stable identity, configuration,
signer, source and desired proxy were preserved. Actual 1 CPU/2 GiB/512 MiB swap,
direct I/O and zero cgroup OOM were verified. The candidate was not installed
during that recovery. Its separate outcome provenance is bound to digest
`6ed34ba03bb869b5fcf5f9ada502337735d3fbf38e99c31b599392f47c3e5189`.
Fleet qualification under v0.1.33 is still pending.

This is a host-backend update. The v0.1.32 C runtime, cold UI writer, daemon APK,
source-built Bluetooth HAL/CFI qualification, official input, frame pacer and
qualified render contract are unchanged. It does not require a new runtime
image or rotate native identity, storage, signers or proxy settings. Existing
failed verification and historical fault records remain evidence; they are not
converted into successful runtime qualification.
