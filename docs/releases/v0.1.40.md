# v0.1.40: restore retained hostnames during native convergence

An already-applied Pixel 6a instance can keep its correct native hostname
sidecar while the live `net.hostname` property is empty after recreation.
Native convergence now restores that exact retained value when needed and
verifies the actual property before reporting the identity applied. It
allocates no replacement hostname and uses no default. Pending GEN targets
and legacy non-Bluejay paths retain their existing ownership and behavior.

This release retains v39 managed native identity reservations before journal
preparation, current and pending claim checks, exact-target recovery after
unknown acknowledgements, native SIM readback, and independent observations
for running devices without an assigned script or APK. Fleet guarantees require
coordinated managed-writer activation and complete current-cohort enrollment;
retired historical values and unmanaged CLI writers remain outside that scope.

Validation includes 17 native-function and real-store tests on Python3.8 and
3.14. Six live instances with naturally missing hostnames passed the complete
owning convergence path: one hostname setter on the first pass and none on the
second. Other native identities, SIM epochs, profile/sidecar bytes, runtime,
storage, resource limits and artifacts stayed unchanged.

The host-Python fix preserves both runtime-image input keys and all 24 artifact
identities. It reuses the existing licensed asset (`d611d149...`), daemon DEX
and ELF outputs. Installer and wrapper references advance to v0.1.40.

Build fingerprints describe the installed build and may match across devices.
These checks do not establish physical Pixel hardware, Google certification,
hardware attestation or provisioned DRM. The inherited IMEI TAC is not verified
as manufacturer-issued for Pixel 6a. Native declared identities and ordinary-app
API observations remain separate measurements.
