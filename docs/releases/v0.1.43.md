# v0.1.43 — recover official input registration and use physical capacity

A native touchscreen can remain valid in the kernel while Android's EventHub and InputReader no longer list it. The fresh-device resource preflight previously rejected that state before the existing official input recovery could run. Repeating the scenario therefore produced `fresh6a_official_input_not_ready` without restoring the missing registration.

Explicit resource and profile actions now validate their existing immutable resource contract, then use the existing guarded same-inode reannouncement only when input is not ready. A fresh kernel/service probe, EventHub path, display epoch and coordinate mapping must pass before the action succeeds. Read-only `verify_runtime` remains read-only, and healthy input takes the original fast path. No pointer event, ADB input fallback, new input driver, device identity change, APK change or image replacement is introduced. Failed mapping reads retain a bounded diagnostic reason.

Default capacity now reserves one GiB of physical RAM for the host instead of ten percent, while retaining the existing CPU reserve and explicit override options. Device slots still require one CPU and two GiB of physical RAM; swap never increases that capacity. For the measured fleet's 21 hosts with four vCPUs and approximately 7.55 GiB RAM and one host with eight vCPUs and approximately 15.21 GiB RAM, this yields 70 slots: three on each small host and seven on the larger host. This calculation does not create or remove devices by itself.

Regression tests cover the captured missing-registration state, healthy no-op behavior, read-only failure, profile changes, unverified repair, wrong event-node evidence, runtime handoff, and physical capacity with explicit reserves. Live qualification and rollout results are recorded separately from these source tests.

On the affected live instance, a controlled invocation restored the missing registration in 13.66 seconds through the existing official reannouncement path. The event node, inode, service binding, 13 native identities, Build values, container, image and resource limits stayed unchanged. The nine-point mapping proof passed at 1080×2400 without sending a pointer event, and a second healthy invocation requested no repair. Normal application-loop and capacity-rollout observations are separate follow-up checks.
