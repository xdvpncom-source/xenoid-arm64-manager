# v0.1.49 — confirm VPN authorization and recover notification shades

An advertisement can open Google Play immediately after Connect, before the scenario observes Android's granted VPN permission. The scenario previously waited for permission until its deadline despite `ACTIVATE_VPN: allow` being present for the assigned package.

During the pre-ad-dismissal permission stage (`ads=False`), a readable, unobstructed window from a package in `AD_LANDING_PACKAGES` can now accompany that exact target-package permission proof. This does not establish tunnel connectivity. Loading, missing hierarchy, crash, terms, notification and just-handled-action checks remain in place. Unconfigured foreign windows and the `ads=True` path retain their previous behavior.

The exact `com.android.systemui/NotificationShade` window is now collapsed using the existing fresh, verified official Back action in startup, permission, waiting and ad phases. Notification items and Dismiss all are never selected as ad-close controls. Other SystemUI windows are unchanged; missing or stale navigation proof sends no input. A fresh target-app observation is still required after closing the shade.

The scenario still completes its full random 90–120-second dwell before any configured-store Back action or ad dismissal. Every input continues through the existing official Xenoid native path. The runtime now also offers Back for a stable parsed system-window title without requiring that title to contain an app package. It retains the original focus tuple and still rechecks that tuple, display geometry, fresh Back node, SystemUI owner and input routing before the official touch. No APK, device identity, memory limit or resource policy changes in this release.

Regression tests cover granted and denied target authorization, unconfigured and removed store packages, unchanged `ads=True` behavior, a complete 120-second dwell without early input followed by one verified native Back, and exact notification-shade recovery with stale-proof/cooldown/foreign-window rejection. Live qualification is recorded separately.

Live qualification completed in two separate runs. The full assigned-APK permission canary completed one timed app cycle with six official input actions and no errors. The focused shade canary started on the raw `NotificationShade` window, sent the verified native Back, and returned to the assigned app with three official actions and no errors; it closed the app while preserving its data. The latter used the candidate runtime helper in a newly started worker and was a startup-only check, not another full timed cycle.
