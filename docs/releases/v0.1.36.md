# v0.1.36: stock window roots and persistent memory headroom

Android's stock accessibility dump can wrap an application's root in a
`hierarchy` element. The window parser now accepts both supported same-window
root shapes. It continues to reject ambiguous roots, a foreign owner, and roots
belonging to a child window. A previously readable Close control no longer
coexists with a falsely missing application root.

The configurable QA cycle can use a freshly observed Android Back control when
a confirmed advertisement exposes no usable Close control. The input travels
through the official Xenoid pointer route. A successful input acknowledgement
does not establish that the ad closed: the normal cycle still requires fresh UI
readiness and its later steps to complete. Bounded diagnostic metadata records
failed ad recovery without retaining screen labels or advertising content.

Memory reclaim headroom is stored in the owned systemd scope's `MemoryHigh`,
as well as checked in the live cgroup. Generation-bound accounting preserves
historical receipts when an instance starts in a new scope. Native startup
applies the configured policy before later readiness work and before an early
`--no-wait` return. The QA installer applies and verifies persistence around its
daemon reload. CPU, RAM and swap hard limits remain unchanged by this policy.

Cold controller staging now includes the host VM isolation dependency in its
complete fourteen-file helper closure. The source bundle explicitly accepts
the complete previous v0.1.35 source set, including its bootstrap regression
file, before performing an upgrade.

APK bytes, profile display settings and official Xenoid input retain their
existing contracts. This source release contains no newly built SystemUI APK;
the separate duplicate-initialization candidate remains unqualified. Source
tests and individual real-device observations do not establish universal or
long-running fleet stability.
