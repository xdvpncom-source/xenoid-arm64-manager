# v0.1.52 — Android user preferences after regeneration

The shared scenario exposes `UI_PREFERENCES` for per-regeneration Android locale, time zone, date/clock format, font scale and light/dark mode. Defaults are US-only: `en-US`, four US time zones, font scales of 0.85, 1.0 and 1.15, and light/dark mode. The explicit `native_location` request also moves existing devices to the US and selects T-Mobile, AT&T Mobility or Verizon Wireless through the same official GEN. New native devices initialize in the US; existing saved country state is retained until an explicit GEN requests the move.

The worker prepares the official native runtime, captures the device’s original settings and pins one selection before native identity mutation. It applies and verifies that selection after native/profile completion, before the existing Google cleanup stages. Retries reuse the saved selection. Existing saved selections keep their original algorithm; new selections account for Android’s float32 font-scale readback when excluding the current settings. A requested country/carrier change is recorded as a complete `locationTarget` in the native journal and matched to the reserved SIM sidecar; legacy journals keep their original behavior.

The daemon helper uses Android’s configuration, alarm and UI-mode services and bounded `cmd settings` operations. It preserves absent settings as absent, checks exact readback and attempts rollback after a failed application. `qa/restore-device-region.py` restores the first native country through a fresh official GEN, then restores the original UI settings. `qa/restore-ui-preferences.py` remains the UI-only rollback. Disable `UI_PREFERENCES` first to keep later regenerations from choosing another profile, and retain the private baseline files while rollback is needed.

Native Google exit-history parsing now accepts localized decimal digits in timestamps. Arabic output previously caused a false process-stability failure and blocked GEN preparation. The existing crash, ANR, boot-time and severity checks remain in place. The current Android image’s ICU formatter was checked against all 50 regional presets; every timestamp parsed back to the expected UTC second.

Android's valid `UNKNOWN` and `PERMISSION_CHANGE` exit reasons are recognized. Unknown causes are counted in `unknownExitCount`, without being labeled as proven crashes. A recorded regeneration from an older script run can finish under its current worker through an explicit recovery handoff. The original request, source, transaction and receipt remain fixed; each recovery reservation and finalization requires a fresh read of all 13 identities before acknowledgment.

Replacing a stopped run during GEN preserves its original transaction. A separate terminal handoff verifies the stopped worker and retained receipt before the queued successor starts; it does not reserve identities or acknowledge completion. The successor still uses the normal fresh-read recovery checks.

The daemon is built and signed with the existing host key. Existing devices may receive that daemon through normal official preparation; new hosts receive the same source from the installer. The VPN APK, official touch path, display configuration and hard container resource limits are unchanged. The Bluetooth native asset archive is unchanged.

Android setting verification does not establish how every app chooses its language, theme or text sizing. App and WebView behavior must be observed separately.
